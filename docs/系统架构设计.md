# 外部 Agent 执行监控与质量评估平台 · 系统架构设计

版本：v1.0（设计稿）  
课题依据：[介绍.md](介绍.md)  
现有实现：[Python 采集器](../collector/claude_collector.py)；历史原型：[PowerShell Demo](../scripts/claude_monitor_demo.ps1)

## 1. 项目定位与范围

平台**复用现成 Agent 的执行能力，自己实现调度、观测和评估**。用户选定测试任务、Agent 和执行策略后，平台启动实际的 Claude Code CLI，而不是自己调用模型 API 模拟 Agent。待首版验收后，再接入 Codex；新增适配器不应要求重写评估模块或前端页面。

| 范围 | 决策 |
| --- | --- |
| 首版（MVP） | 本机、单用户、串行执行；Claude Code CLI 托管运行；事件时间线、资源摘要、独立评估、两种策略对比。 |
| 后续扩展 | Codex 适配器、批量实验、通过显式配置的 Hook 或遥测采集用户自行启动的会话。 |
| 不做 | 接管未配置的 IDE 会话、嗅探网络流量、采集模型隐藏推理、开放任意命令与工作目录、用模拟数据替代真实实验结果。 |

**原型验证过的事实：**在 Windows 上，PowerShell 5.1 原型成功启动 Claude Code 2.1.302，对无工具任务采集到 14 条有效 JSONL 事件（包含一次 API 重试），校验得到 `DEMO_OK`；1 秒超时返回 `124` 并保留 3 条事件；不存在的工作目录在启动前被拒绝。CLI 将当时的 `sonnet` 报告为 `gpt-6.2-sol`，同时打印模型识别告警但仍正常结束。该实验验证的是 CLI 事件链路，**不是**特定官方 Claude 模型的性能，也未验证工具配对、进程树回收或交互式监听。

## 2. 总体结构与技术选型

```text
React Web 界面：选任务 / 发起运行 / 查看时间线 / 比较策略
          │ REST 提交与查询；SSE 订阅运行事件
          ▼
FastAPI 模块化单体 ── 运行服务 / 事件查询 / 实验统计
          │ 使用 SQLite 持久化队列、状态、事件和评价
          ▼
同一应用中的单执行 Worker（Web 服务只启动一个进程）
          ├─ 工作区管理：复制固定测试夹具、隔离每次运行
          ├─ 进程监督：启动、限时、退出、清理
          ├─ Claude Code 适配器 ── stdout JSONL / stderr / 退出码
          │                        （后续：Codex 适配器）
          └─ 独立验证器 ── 检查结果文本或工作区产物
```

| 层 | 技术 | 理由 |
| --- | --- | --- |
| 后端与执行 | Python 3.12、FastAPI、Pydantic、`asyncio` | 同一语言实现 API、子进程采集、验证器和统计规则。 |
| 存储 | SQLite（WAL + 短事务）、SQLAlchemy、Alembic | 本机单写入任务足够；迁移管理表结构。有多实例并发需求再换 PostgreSQL。 |
| 界面 | TypeScript、React、Vite、Ant Design；需要图表时加 ECharts | 首先交付任务表单、运行时间线和对比表，不先做复杂看板。 |
| 验证 | pytest、脱敏 JSONL 样本、真实 CLI 冒烟测试 | 离线覆盖边界，真实调用验证兼容性。PowerShell 脚本保留为诊断基线，不作为正式 Worker 的依赖。 |

开发前置：安装 Python、Node.js LTS 和本机原生 `claude.exe`；确认 CLI 登录、可用模型配置和测试预算。先在终端验证 `claude --version` 与无工具流式输出。后端绑定 `127.0.0.1`，首版无 Redis、Celery、API 代理或 OpenTelemetry Collector。

## 3. 执行与采集设计

### 3.1 一次运行如何完成

1. 用户提交 `task_id`、`agent_id` 和 `strategy_id`。服务校验任务与策略能力，保存不可变的任务版本、期望结果、策略和超时等配置快照，创建 `queued` 记录。
2. Worker 串行领取任务。复制干净夹具到 `workspace_root/<run_id>`，记录 CLI 版本和工作区标识；以该目录为子进程 `cwd`，不传不存在的 `--cwd` 参数。由适配器构造参数数组，不经过 Shell。
3. 实时逐行读取 stdout 并解析 JSONL；同时排空 stderr，避免管道堵塞。事件先入库，再由 SSE 提供给网页；刷新页面不影响运行。对行长、保存量和诊断摘要设上限；遇到无效行记录计数，未知类型保留事件类型等有限元数据，不导致整个运行崩溃。
4. 运行结束后检查进程退出码和 CLI 终态。Claude Code 需要退出码 `0` 且收到成功的 `result`；退出码 `0` 但缺少 `result` 属于协议不完整。stderr 中的告警单独保存，不直接当作失败。
5. CLI 成功并清理进程后，用独立验证器检查真实结果。验证器不听信 Agent 自称成功，也不执行 Agent 生成的命令。评估异常标记为 `unavailable`，不计作模型答错。

执行状态：`queued → running → succeeded | failed | timed_out | interrupted`。超时使用单调时钟并保留已有事件。首版不对异常运行自动补跑：服务重启后先确认遗留进程已清理，再把未完成的 `running` 标记为 `interrupted`；没有被领取的 `queued` 可继续执行。**Windows 进程树回收是工具任务的验收条件**：正式 Worker 使用 Windows Job Object（父进程退出时清理；实现需验证绑定不留逃逸窗口），真实测试确认没有遗留子进程后再启用工具任务；现有脚本只验证了 CLI 超时退出。

### 3.2 适配器契约与 Claude Code 映射

- `capabilities()`：报告当前适配器可以暴露哪些事件与资源统计，供策略校验和界面使用。
- `build_launch_spec(run)`：输出可执行文件、参数、工作目录和受控环境配置；进程生命周期仍由通用监督器负责。
- `parse_line(line)`：把 CLI 输出映射为统一事件；`summarize_exit()` 根据结构化终态和退出记录给出执行摘要。

| Claude Code 来源 | 平台事件或字段 | 说明 |
| --- | --- | --- |
| `system/init` | `session_started`、`session_id`、实际报告的模型和 CLI 版本 | 同时记录请求的模型别名与实际模型名。 |
| `assistant` 中的 `tool_use` | `tool_requested` | 表示 Agent 提出调用，不等同于已经执行。 |
| `user` 中的 `tool_result` | `tool_result` | 使用 `tool_use_id` 配对，允许缺失或乱序；结合 `parent_tool_use_id` 表示层级。 |
| `system/api_retry`、权限拒绝 | `api_retry`、`permission_denied` | 重试、告警和最终失败分别统计；只统计可观测事件。 |
| `stream_event` | 可选流式进度 | 不重复计为一次消息、工具调用或模型请求；首版页面可省略逐 Token 分片。 |
| `result` | `agent_result`、`usage`、`total_cost_usd`、终态 | 记录来源和统计口径，缺失值为 `null`，成本为 CLI 估算，不是账单。 |
| 进程监督器 | 启动、退出、超时、耗时 | 所有适配器都具备；跨策略比较用平台侧墙钟耗时。 |

Claude Code 首版以 `-p --output-format stream-json --verbose` 获取结构化事件。冒烟任务维持 `--safe-mode`、手动权限、禁用工具且不复用会话；只读任务验证时按策略仅提供所需的文件读取能力。不得把消息数量当作模型 API 调用次数，也不通过消息到达时间推断精确工具耗时。以后通过 Hook 补充工具前后触发时点，通过 OTLP 补充可观测的请求级指标；不同来源按原生 ID 或明确关联键关联，不凭时间接近就合并，更不能将两路重复计数。

## 4. 数据和接口

| 表 | 关键字段 | 用途 |
| --- | --- | --- |
| `task_cases` | id、version、任务文本、夹具版本、验证器类型、期望值 | 版本化测试任务。首版可由本地清单导入。 |
| `runs` | id、task_id、experiment_id（可空）、agent_id、配置快照、状态、退出码、开始/结束时间、session_id、资源摘要、错误分类 | 一条记录表示一次运行；重试或重新发起是新的记录。 |
| `run_events` | run_id、seq、kind、source、observed_at、native_id、tool_use_id、parent_tool_use_id、脱敏摘要 | `(run_id, seq)` 唯一；`seq` 是平台接收顺序，不代表跨源因果顺序。 |
| `evaluations` | run_id（唯一）、evaluator_version、status、checks、duration_ms | 评估状态：`passed` / `failed` / `unavailable` / `not_run`。与执行状态分开。 |
| `experiments` | id、实验配置快照、创建时间 | 关联同一批配对运行；在策略比较阶段引入。 |

`GET /api/tasks` 查询可用任务；`GET /api/agents` 查询适配器和策略；`POST /api/runs` 创建运行并返回 `202` 与运行 ID；`GET /api/runs/{id}` 查询摘要和评估；`GET /api/runs/{id}/events?after_seq=...` 分页回放；`GET /api/runs/{id}/stream` 通过 SSE 推送事件，以 `seq` 作为事件 ID，断线使用 `Last-Event-ID` 从持久化记录补齐。前端按序号去重。首版 SSE 可以短间隔查询数据库，不需要消息中间件。

默认仅存用于时间线和评分的必要字段；结果文本按任务约定限长，工具参数、工具结果、完整 prompt 和 stderr 原文不默认持久化。原型 raw JSONL 与正式系统数据分开保管。API 不接受前端提交的任意路径、CLI 参数、环境变量或命令；工作区路径由后端生成，只使用可信夹具，拒绝能跳出目录的链接或重解析点。工具白名单不等于 OS 沙箱；不接收陌生仓库或远程用户任务，不授予 Shell、任意写入或跳过审批权限。离线验证器和期望答案不复制到 Agent 可读的任务夹具中。

## 5. 评估和论文实验

第一组任务采用小型、可客观判定的夹具：无工具任务返回固定文本；只读任务从固定文本文件提取标记，以答案精确匹配为独立校验，辅以实际出现配对的读取工具事件。平台把**CLI 执行成功**与**答案正确**分开，不依赖模型自评，也不先设计任意加权总分。

**策略对比**可使用同一 Claude Code CLI 与同一实际模型，唯一改变读取工具是否可用。按相同任务、提示词、夹具、超时和执行环境配对运行，每次使用新会话和干净工作区；预先固定任务集、每组重复次数与预算，交错执行两种策略并记录失败，不只筛出成功样本。若新增 Codex，明确比较的是「CLI + 模型 + 策略配置」组合；未控制模型时，不把差异归因于 CLI 本身。

| 指标 | 统计口径 |
| --- | --- |
| 端到端任务通过率 | 验证通过数 / 纳入对比的运行数。Agent 失败或超时计未通过；验证器故障单列，可事先规定成对剔除并报告剔除数量。 |
| 运行可靠性 | 单列正常完成、启动错误、协议不完整、权限拒绝、超时等类别及样本数；非致命告警单列。 |
| 执行效率 | 报告全部运行的墙钟耗时中位数；样本足够再报告 P95，并可另外给出成功组耗时。验证器耗时单列。 |
| 资源消耗 | 报告有数据的运行数和覆盖率，以及有数据样本的输入/输出 Token、缓存 Token、估算成本；不填零、不把重叠口径求和。 |

## 6. 落地顺序与验收条件

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1. 正式采集器 | Python 适配器、进程监督、事件规范 | 用脱敏样本覆盖坏行、未知事件、stderr 告警、退出 `0` 无结果和超时；真实无工具任务返回 `DEMO_OK`，能回放初始化和最终结果。 |
| 2. 只读工具与独立评估 | 固定文件夹具、工具配对、外部校验 | 用真实 CLI 获取同一 `tool_use_id` 的请求和结果；核对输出。另验证错误答案会判失败、超时不会留下受控子进程。 |
| 3. 平台闭环 | SQLite、API、运行列表、事件时间线和评估详情 | 从网页发起真实运行；断线重连不丢事件、不重复展示；服务重启后能查询既有记录。 |
| 4. 策略对比 | 固定实验配置、指标统计和对比页面 | 同一套任务可复跑；统计结果可从运行和评估明细重新计算；样本数与缺失比例可见。 |
| 5. 后续扩展 | Codex 或显式注册的 Hook/遥测通道 | 新来源复用统一数据结构和评估器；交互式采集与托管运行分别标明能力和覆盖率。 |

本设计稿不代表正式平台已经实现。当前可复用的是 PowerShell 原型的测试经验和事件样本；下一个实现任务是 Python 适配器与解析测试，不需要先写前端或部署数据库服务。
